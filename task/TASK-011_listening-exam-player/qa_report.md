## 2. Security Assessment
- [x] Pass (tidak ada secret hardcoded, tidak ada IDOR, tidak ada injeksi header/path, tidak ada kebocoran kunci jawaban)

### Endpoint `GET /attempts/{id}/audio` (terverifikasi)
- **IDOR/otorisasi:** query awal `WHERE id = :attempt AND user_id = :sesi` (`audio.ts:46`) -> bukan milik = `404 NOT_FOUND` (bukan 403, tidak ada oracle keberadaan); tanpa sesi `401` oleh `requireUser`; `must_change_password` diblokir `withApi`. Path `attempt_id` `Uuid` strict (400 bila bukan uuid). Kunci audio dirujuk hanya lewat `set.listeningAssetId` dari attempt; tidak ada parameter `asset_id`. Query `section` (Boss) harus uuid, harus anak set induk (`parentSetId = set.id`) dan `state.sections[section].phase === 'ACTIVE'`; diabaikan untuk non-Boss; tanpa `section` pada Boss = 404.
- **Penegakan kunci audio (server):** hanya `IN_PROGRESS` dan belum lewat `deadline+5 dtk` (`isExpired`); setelah submit/expire/abandon = `409 ATTEMPT_NOT_ACTIVE` sehingga audio tidak dapat diambil ulang pascaujian. Sesuai Non-Goals spec 011 dan `security-standards.md` 6.3.7/17.6, "satu kali putar" TIDAK ditegakkan server (Range ulang selama attempt aktif tetap dilayani); ini risiko diterima yang terdokumentasi (lihat F-11-07), bukan cacat.
- **Path traversal:** `storage_key` dari DB, bukan input; `FsStorageDriver.resolve` memvalidasi `validKey` (shard 2-hex atau direktori allow-list + nama UUID + ekstensi 1-5 alnum) lalu memastikan `full` di bawah root. Tidak ada `..`, tidak ada absolut. `size()` menolak non-berkas (`isFile`).
- **Header injection:** semua nilai header berasal dari konstanta, angka (`Content-Length`, `Content-Range` dari integer yang sudah divalidasi `Number.isSafeInteger`), atau `Content-Type` dari peta allow-list `SERVED_MIME` (bukan nilai DB mentah; WAV varian dinormalisasi). Tidak ada nama berkas/`Content-Disposition` dinamis (`inline` polos), tidak ada `ETag`/`Last-Modified` sehingga `If-Range`/`If-None-Match` tak relevan.
- **Penanganan Range:** satu rentang; multi-rentang dan satuan non-`bytes` = 200 penuh; bentuk cacat, `start >= total`, `start > end`, `-0`, angka melebihi `MAX_SAFE_INTEGER` = 416 dengan `Content-Range: bytes */total`; ujung dipotong ke `total-1`; sufiks > ukuran = seluruh berkas; berkas kosong ditangani (`size<=0` -> 416 bila ada Range, 200 body `null` bila tidak). Stream `createReadStream({start,end})` -> `Readable.toWeb` (pembatalan klien menutup fd; ada tes). Tidak ada penggandaan memori.
- **Kebocoran metadata:** respons error memakai envelope standar; log `asset_file_missing` hanya `assetId` (tanpa path). `AttemptDTO.listening` hanya `audio_url` (berbasis attempt_id), `mime_type`, `duration_sec`; tidak ada `asset_id`/`storage_key` (diuji `JSON.stringify(dto)` tidak memuat `asset.id`). 409 vs 404 untuk attempt MILIK SENDIRI membocorkan status sendiri saja.
- **Cache:** `Cache-Control: private, no-store`, `nosniff`, `Cross-Origin-Resource-Policy: same-origin`, `Content-Disposition: inline`; `passthrough` di `withApi` mempertahankan semua header dan menambah `X-Request-Id`.
- **Rate limit:** bucket `general_user` 300/menit (spec) ada; lihat F-11-02 untuk amplifikasi bandwidth.
- **Kunci jawaban di mode ujian:** tidak ada perubahan pada DTO soal; pemutar tidak menerima/menyimpan data jawaban. `localStorage` `audio:v1:{attempt}` hanya `{position_sec}` (divalidasi angka finit >= 0); dapat diubah pelajar sendiri (mengulang/melompati audio) = kontrol UX, risiko diterima.

### Keputusan FE soal `aria-readonly` pada progressbar: VALID, perlu pencatatan spec
Spec 011 meminta `role="progressbar"` + `aria-readonly="true"`. QA memeriksa `aria-query` (basis aturan axe/jsx-a11y) di `node_modules`: properti yang didukung `progressbar` hanyalah `aria-valuemin/max/now/valuetext` (+ atribut global); `aria-readonly` didukung `slider`, bukan `progressbar` (atau `meter`). Jadi menambahkan atribut itu memang melanggar `aria-allowed-attr` (axe) dan WCAG 4.1.2, dan keputusan FE melepasnya benar. Alternatif yang tetap memenuhi maksud "tidak dapat digeser": tetap `progressbar` (kini), karena `role="slider"` + `aria-readonly` akan diumumkan sebagai kontrol yang dapat disetel. Namun lihat F-11-04 (spec/AC belum diubah; `data-readonly` bukan atribut yang dibaca teknologi bantu; `aria-valuemax` dapat sama dengan `aria-valuemin`).
