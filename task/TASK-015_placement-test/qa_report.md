### Terverifikasi baik

**Penegakan hasil Placement (apply tidak membuka Tier tanpa hasil sah)**
- `recommended_tier` dihitung server saat finalisasi dan disimpan di `attempts.result_json` (`placement.ts:238-258`); `POST /placement/apply` membaca nilai itu dari baris attempt yang dikunci, bukan dari klien (`placement-service.ts:55-68`). Body `strictObject {attempt_id, tier_number 1-4}` (`contracts/placement.ts`); `tier_number > recommended_tier` -> 409 `TIER_ABOVE_RECOMMENDATION` (`placement-service.ts:68`), jadi klien tidak bisa naik di atas rekomendasi.
- Urutan pemeriksaan apply: `loadLocked` (milik pengguna, `FOR UPDATE`) -> tipe harus `PLACEMENT_TEST` (404) -> attempt kedaluwarsa dinilai dulu -> `IN_PROGRESS/ABANDONED` ditolak `ATTEMPT_NOT_FINISHED` -> baris `users` dikunci `FOR UPDATE` dan `applied`/`placement_completed_at` -> `PLACEMENT_ALREADY_APPLIED` -> `PROGRESS_EXISTS`. Tidak ada jalur apply tanpa attempt Placement selesai milik pengguna itu.
- **SKIPPED vs COMPLETED**: efek hanya `GatekeepingService.applyPlacementResult` (`gatekeeping/service.ts:404-426`; satu-satunya pemanggil `placement-service.ts:76`) menandai Tier/Modul/Sub di bawah Tier terpilih `SKIPPED` dengan `unlock_source='PLACEMENT'` (monoton: hanya dari LOCKED/UNLOCKED, `skipEntity` baris 347) dan membuka Tier terpilih hanya bila `LOCKED` -> `UNLOCKED`. Placement tidak pernah menulis `COMPLETED` atau `boss_passed_at`. `users.placement_completed_at` hanya ditulis di `gatekeeping/service.ts:425` (grep `src/`).
- **Tidak dapat membobol gerbang Tier/Boss pada atau di atas Tier terpilih**: Tier N+1 hanya terbuka bila Tier N `COMPLETED` (Boss lulus) atau `SKIPPED` (`gatekeeping/rules.ts:127-131`); Placement tidak menyentuh Tier > terpilih, sehingga Boss Tier terpilih tetap wajib. Tier di bawahnya yang `SKIPPED` memang melewati Boss-nya (dirancang, ADR/CUR-04) dan Boss untuk Tier itu menjadi `BOSS_ALREADY_PASSED` (`rules.ts:218`), jadi tidak dapat diambil ulang. Konsep Tier berbayar/langganan tidak ada pada produk ini (lokal, tanpa pembayaran; `requirements.md` "tanpa API berbayar"), sehingga "bobol gerbang berbayar" tidak berlaku. Kelemahan yang nyata ada pada seberapa mudah rekomendasi tinggi diperoleh: F-15-01.
- Skip Test setelah Placement: `skipEligible` hanya LOCKED/UNLOCKED tanpa sub dimulai (`rules.ts:223`), jadi Tier yang sudah `SKIPPED` tidak dapat di-Skip lagi.

**Kebocoran bank soal / difficulty / kunci**
- `state.order`/`state.served` hanya memuat soal yang dijawab ditambah satu `pending` (`placement.ts:132-143`); `GET /attempts/{id}` mengembalikan `state.order` saja (`dto.ts:112-117`) sehingga soal bank lain tidak terkirim, dan memuat soal `pending` plus `answers` untuk yang sudah dijawab, sehingga catatan FE-3 terpenuhi (tes `placement.itest.ts:191`). `toPublicQuestion` (`engine.ts:127`) adalah allow-list: tidak ada `difficulty`, `correct_answers`, `explanation_id`. `difficulty` hanya di `state.placement.history` dan tidak pernah diserialisasi; `result_json.placement` hanya memuat `{recommended_tier, ability, correct_count, served_count, applied, tier_options}`. `feedback` selalu `null` (`placement.ts:149`), `review` disembunyikan (`HIDE_REVIEW_TYPES`, `dto.ts:128`, ADR-003 #27).
- `PUT` soal belum tersaji -> 404 (`placement.ts:100`), soal sudah dijawab -> 409 `QUESTION_ALREADY_ANSWERED` (sama atau beda, `placement.ts:101`), tersaji bukan `pending` -> 409 `QUESTION_NOT_CURRENT`. Jawaban tidak dapat diubah, sehingga soal tidak dapat dipakai sebagai oracle benar/salah (tidak ada feedback sama sekali).
- Pemetaan opsi diacak dengan `state.rng_seed` rahasia CSPRNG (`placement.ts:88-89,137,198`); id opsi opak; seed tidak dikirim ke klien.

**Race / idempotensi**
- `PUT answers`: `loadLocked` `FOR UPDATE` lalu `QUESTION_ALREADY_ANSWERED`/`NOT_CURRENT` diperiksa dari `answers` yang dibaca setelah kunci; dua perangkat serentak -> satu 200 dan satu 409 tanpa soal ganda tersaji (tes `placement.itest.ts:247`). `POST /attempts` serentak: advisory lock per (user,set) + partial unique `attempts_one_active_uq` (`db/schema.ts:377`). `POST /submit` ganda idempoten (`service.ts:414-417`): kasus catatan FE-4 terpenuhi untuk attempt `GRADED/SUBMITTED/EXPIRED`. `apply` serentak: kunci attempt lalu kunci `users`, satu 200 dan satu 409 (tes `placement.itest.ts:501`, audit sekali).
- Catatan FE-4 untuk attempt kedaluwarsa: PUT/GET/result/apply menilai `EXPIRED` lebih dulu dari jawaban yang ada lalu melanjutkan (`service.ts:313-316`, `placement-service.ts:58-61`); respons pertama yang memicu penilaian adalah 409 `ATTEMPT_EXPIRED` (klien menanganinya lalu `POST /submit` mengembalikan hasil idempoten).

**Waktu**
- `deadline_at = started_at + set.time_limit_seconds` dari jam server (`service.ts:265`); toleransi 5 dtk; hasil kedaluwarsa dihitung dari soal yang dijawab (tanpa jawaban -> Tier 1).

**Anti-abuse / satu kali per akun**
- Dalam satu set: attempt `IN_PROGRESS` di-resume (bukan baru); setelah selesai, `placementEligibility` memblokir `RESULT_PENDING_APPLY` sampai apply, lalu `ALREADY_COMPLETED` (`placement.ts:104-134`). Akun dibuat lewat undangan admin (ADR-003 #15), sehingga pembuatan akun massal untuk mengulang tes tidak tersedia. Celah lintas-set: F-15-03.

**Determinisme dan keamanan acak**
- Pemilihan soal memakai `mulberry32(seedOf(attempt.id))` (D3 apa adanya); analisis keterprediksian di F-15-02. Pengacakan opsi/urutan tidak memakai id publik (CSPRNG), sesuai penutupan F-06-01.

**Vektor uji D4 diperiksa terhadap kode** (`placement-rules.ts:51-58`): `abilityH = floor((2*sum*100 + len) / (2*len))` (setengah ke atas, bilangan bulat), `served=0` atau `correct*100 < 32*served` -> Tier 1, selain itu `clamp(floor(ability),1,4)`. Hasil cocok dengan seluruh vektor spec.

**OWASP lain**
- Injeksi: kueri `user_sub_module_progress` memakai `sql` template terparameter dengan cast `::uuid` (`placement.ts:55`, `placement-service.ts:65,70`); selebihnya drizzle. CSRF/origin lewat `withApi` (metode POST). Tidak ada secret pada berkas yang direview. Galat tidak membocorkan detail. Audit `PLACEMENT_APPLIED` mencatat `tier_number`, `recommended_tier`, `ability` (tanpa PII).
- **Frontend**: tidak ada `dangerouslySetInnerHTML`, `console.*`, `localStorage`/`sessionStorage` pada `components/exam/placement`, `components/home/placement-entry.tsx`, `lib/api/placement*.ts` (grep bersih). `next_question` divalidasi `QuestionPublicSchema` (tidak sesuai kontrak -> toast galat, soal tidak maju, tanpa penambalan); gagal jaringan setelah server menerima jawaban pulih lewat 409 `QUESTION_ALREADY_ANSWERED` -> `resync` dari `GET /attempts/{id}` (`placement-session.tsx:122-127`). Klien hanya mengirim `attempt_id` + `tier_number`; kelayakan diputuskan server; redirect konstan `/peta`; `<select>` hanya mengubah state, nilai tetap divalidasi server (400/409). Teks server dirender sebagai teks React. Tautan hanya `/ujian/mulai/{uuid}` dan `/ujian/{uuid}[/hasil]` dari respons tervalidasi Zod.
