Evaluasi `SELF_ASSESSMENT` dan `injection_suspected` dikecualikan (`boss-rules.ts:75`). Akibatnya W/S tidak dapat meloloskan maupun menggagalkan (ADR-003 #1, #17, security-standards bagian 5 butir 6). Tes: `boss.itest.ts:579`.

- **Gerbang dibekukan saat mulai** (`boss.ts:444,461-471`, `state.boss`): perubahan `boss_gate_*` saat ujian tidak mempengaruhi attempt berjalan; `scoreBoss` memakai `state.boss` (`boss.ts:350-351,390`).

**Race / idempotensi**
- Semua tulis section dan jawaban memakai `loadLocked` = `SELECT ... FOR UPDATE` pada baris attempt milik pengguna (`attempts/store.ts:7-17`; `sections.ts:27,73`). `POST /attempts` serentak diserialkan `pg_advisory_xact_lock` per (user,set) (`service.ts:221`) ditambah partial unique `attempts_one_active_uq` (`db/schema.ts:377`), sehingga tidak ada attempt Boss paralel untuk set yang sama dan cooldown/batas harian tidak dapat dilewati lewat paralelisme (hitungan D4 dan insert berada di bawah kunci yang sama).
- `POST /attempts/{id}/submit` ganda/serentak: status `GRADED` dibaca setelah kunci dan dikembalikan idempoten tanpa `finalize`/hook (`service.ts:414-417`); tes `boss.itest.ts:619`. `start` section serentak: pemanggil kedua melihat `ACTIVE` -> resume tanpa mengubah `started_at/deadline_at` (`sections.ts:48-62`). `PUT` vs `section submit` serentak diserialkan kunci baris.
- Kegagalan menulis `applyBossResult` membatalkan seluruh `submit` (attempt tetap `IN_PROGRESS`).

**Manipulasi waktu / urutan section**
- Semua waktu otoritatif dari `nowDate()` server: `deadline_at` section = `now + time_limit` saat `start` (`boss.ts:316`), attempt = mulai + jumlah time_limit + 1800 (`boss-rules.ts:21-22`). Klien tidak mengirim waktu.
- Urutan ditegakkan (`sections.ts:52-58`): section sebelumnya harus `DONE`; `DONE` tidak dapat dimulai ulang (`SECTION_ALREADY_DONE`); `section_set_id` bukan anak -> 404 (`sections.ts:32`). `PUT answers` memeriksa `question_section` -> hanya soal section `ACTIVE` (`boss.ts:186-200`), toleransi 5 dtk (`SECTION_GRACE_MS`), section kedaluwarsa ditutup `EXPIRED` dan state di-commit lebih dulu sebelum galat dilempar (return nilai, bukan throw, `service.ts:329-330,405`). Penutupan otomatis section kedaluwarsa pada `start`, `GET /attempts/{id}`, dan `submit section`.
- Pengaman keseluruhan benar: attempt `IN_PROGRESS` lewat `deadline+5s` dinilai `EXPIRED` dari jawaban tersimpan; section `PENDING` = skor 0 (`boss.ts:364`).

**Kebocoran kunci / soal section belum ACTIVE**
- `state.order` dan `state.served` hanya bertambah saat `activateSection` (`boss.ts:300-319`); `buildBossAttemptDTO` hanya memuat soal/teks/audio section `ACTIVE` (`boss.ts:220-245`), kosong setelah selesai. `question_section` (yang memetakan semua soal) tidak pernah diserialisasi; `toPublicQuestion` (`engine.ts:127`) adalah allow-list tanpa `correct_answers`/`explanation_id`/`is_correct`. `review` hasil Boss selalu `null` (`boss.ts:681`, `dto.ts:128` `HIDE_REVIEW_TYPES`, ADR-003 #27) sehingga oracle benar/salah per soal (F-08-01) tidak ada.

**IDOR**

Submission W/S per attempt dibaca setelah kepemilikan attempt terverifikasi (`boss.ts:627`), dan `resolveAttemptQuestion` (`ai/context.ts:26-45`) memastikan `attempt.user_id` = sesi serta soal milik section `ACTIVE`.

**Audio `?section=`** (`attempts/audio.ts:47-60`)
- Wajib: attempt milik pengguna, `IN_PROGRESS`, belum kedaluwarsa; `section` harus anak dari set induk attempt (`parentSetId = set.id`); fase section di `state` harus `ACTIVE` dan belum lewat `deadline+5s` (selain itu 409 `ATTEMPT_NOT_ACTIVE`); tanpa `section` -> 404; section tanpa audio -> 404. `Cache-Control: private, no-store`, `nosniff`, `CORP: same-origin`, batas aliran serentak/penuh per attempt. `audio_url` selalu memuat `?section=` dari kedua pembangun payload (`boss.ts:243,285`). Tidak ada akses via `asset_id`. Replay/unduh audio selama ACTIVE adalah risiko residual yang diterima (security-standards 17.6).

**Cooldown / batas harian**
