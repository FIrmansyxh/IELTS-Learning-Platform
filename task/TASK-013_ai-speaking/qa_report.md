## 2. Security Assessment
- [ ] Fail (1 HIGH: F-13-01; tidak ada secret hardcoded, tidak ada injeksi SQL/XSS/shell, tidak ada IDOR)

### Terverifikasi baik
- **IDOR rekaman:** `serveRecording` memanggil `loadSubmissionRow(db, id, ownerId)` (pemilik lain -> 404) (`speaking.ts:143`); `deleteRecording` memfilter `user_id` dan memakai `FOR UPDATE` (`:184`); admin `ownerId:null` + `auth:'admin'`, audit `ADMIN_PLAYED_RECORDING` (`submission_id`, `owner_user_id`, `ip_hash`) ditulis sebelum aliran dibuka dan gagal-tertutup (`:156-165`). Header `Cache-Control: private, no-store`, `nosniff`, `inline`, CORP `same-origin`; `Content-Type` dari kolom DB (hasil magic bytes).
- **Unggahan:** persetujuan diperiksa SEBELUM body dibaca (`speaking.ts:52`); `readMultipart` menghentikan pembacaan di `maxBytes + 64 KB` (`multipart.ts:56-59`) dan menolak `Content-Length` berlebih; satu bagian `audio`; MIME dari magic bytes (webm EBML + doctype `webm` + tanpa codec video di 4 KB awal, OggS, ftyp brand audio) dan ekstensi/Content-Type klien diabaikan (`audio-type.ts:275-287`); nama berkas `{uuid}.{ext}` oleh `FsStorageDriver.put` dengan `validKey` + cek `startsWith(root)` (tidak ada path traversal, `storage/index.ts:26-44`); direktori `private/recordings` 0700 dieksplisitkan (`:54-58`); `wx` dan pembersihan berkas parsial; berkas dihapus bila transaksi gagal (`speaking.ts:124`). `private/` tidak disajikan statis (hanya rute terotorisasi). `duration_sec` klien diparse tetapi dibuang.
- **Spawn aman:** lihat bagian 1. Direktori sementara `mkdtemp` (0700) per job, dibersihkan di `finally` (`pipeline.ts:505-507`) dan `cleanupStaleTempDirs` > 1 jam saat worker start. Kontainer worker non-root `1000:1000`, `read_only: true`, tmpfs `/tmp`.
- **Consent/retensi:** `consent_recording_at` diisi idempoten + audit; `retention_expires_at` ditetapkan pada tiap status terminal selama berkas tersimpan (`recordings.ts:314-320`); `purgeRecordings` + audit `RECORDING_PURGED(count)`; hook anonimisasi menghapus berkas; `DELETE` menghapus fisik, menolak saat `RECEIVED/TRANSCRIBING`.
- **Injeksi pada transkrip:** transkrip melewati pra-pemeriksaan/netralisasi/pembatas/skema yang sama dengan Writing; `pronunciation_estimated` selalu `true`; durasi untuk kap berasal dari server (tetapi lihat F-13-01).
- **Klien:** `isSecureContext` diperiksa sebelum meminta mikrofon; mikrofon dilepas saat tinjau dan unmount (`speaking-recorder.tsx:319`, `use-voice-recorder.ts:67`); object URL di-revoke; catatan persiapan hanya state memori (tidak dikirim, tidak di `localStorage`); `<audio src>` memakai endpoint milik user (diuji); tidak ada Web Speech API/jaringan pihak ketiga; teks transkrip dirender sebagai teks. Hanya id submission yang disimpan di `localStorage` (bukan audio/transkrip).
- **Urutan consent vs secure-context (deviasi dari spec langkah 2-3):** klien memeriksa secure context/dukungan lebih dulu, lalu consent (`speaking-task.tsx:200`: `!secure || !supported || consented` -> perekam menampilkan kartu HTTPS tanpa dialog consent). **Dapat diterima**, bahkan lebih baik: tanpa secure context mikrofon tidak mungkin dipakai sehingga tidak ada rekaman yang diambil dan meminta persetujuan untuk alur yang tak dapat berjalan adalah menyesatkan; server tetap menegakkan consent (409 sebelum body dibaca), jadi bukan kontrol yang dikendurkan. Saran administratif: catat deviasi ini di spec 013 (langkah 2-3) dan dev_log FE (F-13-11).
