### Terverifikasi baik
- **Tidak ada kunci/pembahasan/`is_correct` bocor selama ujian.** `buildAttemptDTO` (`attempts/dto.ts:41-107`) membangun soal lewat allow-list `toPublicQuestion` (engine.ts:~100), opsi memakai id opak CSPRNG (`randomOpaqueId`), `answers[].feedback` hanya terisi bila `mode==='PRACTICE'` (`dto.ts:71`); `submitAnswer` mengembalikan `feedback: practice ? ... : null` (`service.ts:387`) dan tanpa `is_correct`. `questions` kosong setelah attempt selesai (`dto.ts:97-102`).
- **Setelah ujian**: `buildResultDTO` (`dto.ts:127-134`) menambahkan `correct_answer` dan `explanation_id` HANYA bila `practice`; untuk EXAM hanya `is_correct`, `score`, `max_score`, `response` milik sendiri. Sesuai D10 (lihat F-08-01 untuk risiko residual).
- **`rng_seed` tidak bocor ke klien**: `state` (berisi `rng_seed`, `order`, `served.*_orig_index`) tidak pernah diserialisasi; grep `rng_seed|rngSeed` di `src/` hanya `engine.ts`, `prng.ts`. Tidak ada rute yang mengembalikan kolom `attempts.state`.
- **`deadline_at` otoritatif di server**: `deadline_at = now + time_limit_seconds*1000` dihitung di dalam transaksi start dari jam server (`service.ts:264`); klien tidak mengirim waktu. Masa tenggang 5 detik (`GRACE_MS`) diterapkan konsisten di `isExpired` untuk PUT, submit, GET, dan intro. Submit/PUT terlambat: attempt dinilai `EXPIRED` dari jawaban tersimpan dan efeknya di-commit sebelum galat dilempar (`service.ts:315-318,405-408`: nilai `'expired'` dikembalikan dari transaksi, lalu dilempar setelah commit).
- **Race `POST /attempts` serentak**: `pg_advisory_xact_lock(hashtextextended('attempt:{user}:{set}'))` (`service.ts:214`) menyerialkan start per (pengguna, set); cooldown (D3), batas harian (D4), dan insert attempt semuanya di dalam kunci yang sama, sehingga permintaan kedua melihat attempt `IN_PROGRESS` (resume) atau hitungan yang sudah naik. Tidak ada celah TOCTOU antara hitungan D4 dan insert.
- **Submit serentak -> efek sekali**: `loadLocked` memakai `SELECT ... FOR UPDATE` (`service.ts:44-50`); transaksi kedua menunggu lalu melihat status `GRADED` dan mengembalikan hasil idempoten tanpa memanggil `finalize`/hook (`service.ts:400-403`). `writeAudit(SKIP_TEST_*)` dan `applySkipResult` berada di dalam `finalize` -> tepat sekali. Penilaian kedaluwarsa serentak (GET/POST/PUT/settle) juga lewat kunci baris yang sama.
- **`applySkipResult` hanya via GatekeepingService**: satu-satunya pemanggil di `src/` adalah `exams/skip.ts:162`; `skip.ts` tidak menulis tabel progres langsung (aturan ESLint lulus). Penerapan hasil berada dalam transaksi `finalize` yang sama dengan `attempts.passed`, audit, dan hasil JSON (atomik, kegagalan membatalkan submit).
- **Ambang 85.00/84.99**: `passed` ditentukan SATU kali oleh `isPassed` (`engine.ts:408-412`: `rawH*100 >= passPercent*maxH`, bilangan bulat sentesimal tanpa float) dan diteruskan apa adanya (`skip.ts:155`); `percentH/100` hanya dipakai untuk `skip_best_percent` melalui `toHundredths` (`Math.round(n*100)`, aman untuk 2 desimal). `pass_percent` dibekukan di `state` saat start sehingga perubahan ambang saat ujian tidak memengaruhi attempt berjalan. Batas inklusif benar.
- **Skip hanya untuk Modul/Tier belum dimulai**: `skipEligible(status)` (LOCKED/UNLOCKED) DAN tidak ada sub-modul `isStarted` (`skip.ts:46,63`); diperiksa pada start (`:125`) dan intro (`:138`).
- **Cooldown & batas harian tidak dapat dilewati**: tidak ada status yang dapat dipakai kabur (EXAM `IN_PROGRESS` tidak pernah `ABANDONED`, hanya PRACTICE; `service.ts:217-220`); attempt EXAM yang ditinggalkan dinilai saat deadline+5s lewat melalui `settleExpiredForSet` sebelum start/intro, `submitted_at = deadline_at` sehingga cooldown tetap berlaku. Hitungan D4 memakai `ne(status,'ABANDONED')` dan `started_at > now-24h` (strict, sesuai spec).
- **Otorisasi**: `loadLocked` memfilter `user_id = sesi` -> attempt milik orang lain = 404 (bukan 403); `user_id` tidak pernah dari body; `PUT answers` memakai `strictObject` (`{passed}`/`{score}` -> `unrecognized_key`); `question_id` harus ada di `state.order` (404 bila tidak). CSRF origin/sec-fetch-site diterapkan `withApi` pada metode mutasi; `AttemptIdParamSchema`/`Uuid` memvalidasi path.
- **Rate limit**: `attempt_start` 30/jam, `answer_submit` 60/menit per pengguna.
- **Frontend `ExamRunner`**: tidak ada `localStorage`/`sessionStorage`/`indexedDB`/`console.*`/`dangerouslySetInnerHTML` pada `components/exam`, `app/(exam)`, `lib/api/exams.ts` (grep bersih); tidak ada persistensi cache TanStack Query (`persistQueryClient` tidak dipakai; attempt `gcTime: 0`). Jawaban benar tidak pernah ada di klien karena server tidak mengirimnya; `feedback={null}` ke `QuestionRenderer`. Status `flagged` hanya state lokal. `ExamResult` tidak merender `correct_answer`/`explanation` (grep bersih). Tautan hanya konstanta `/peta`, `/belajar/{kode dari pohon server}`, `/ujian/{uuid}`. Teks galat dirender sebagai teks React (auto-escape).

## 3. Architecture Alignment
- [x] Pass
- `GET /api/v1/exams/{assessment_set_id}/intro`, `POST /attempts` (kode `SKIP_NOT_AVAILABLE` 409, `COOLDOWN_ACTIVE` 429 + `Retry-After` + `details[0]`, `DAILY_ATTEMPT_LIMIT` 429), ekstensi `result_json.skip` sesuai `specifications/008` dan `_api-contract.md`. Tipe handler didaftarkan di `assessmentTypeHandlers` tanpa mengubah `AttemptService` selain `settleExpiredForSet`. Audit `SKIP_TEST_PASSED/FAILED` (`entity_id` = attempt id; spec tidak menetapkan `entity_id`, dapat diterima). Setting `attempt.cooldown_minutes` (0-1440) dan `attempt.max_per_set_per_day` (1-20) tervalidasi registri; nilai dibaca per percobaan sehingga tidak surut.
