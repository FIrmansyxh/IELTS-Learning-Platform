### Terverifikasi baik
- **IDOR / kepemilikan:** `loadSubmissionRow(db, id, userId)` memfilter `user_id` sesi -> 404 (bukan 403) (`ai/dto.ts:134-139`); `retrySubmission`/`selfAssess` memakai `WHERE id AND user_id ... FOR UPDATE` (`service.ts:158,198`); konteks pengiriman: `resolveAttemptQuestion` memfilter attempt milik user dan memeriksa `order.includes(questionId)` (`context.ts:517-522`), `resolveMiniTask` lewat `assertSubModuleAccessible` (`context.ts:535`). `user_id` tidak pernah dari body. Admin: `GET /admin/submissions/{id}` `auth:'admin'` dan menulis `ADMIN_VIEWED_SUBMISSION` (`admin/submissions/[submission_id]/route.ts:10-20`) dengan `owner_user_id` dan `ip_hash`.
- **Kuota/antrean/serentak:** `lockUserSubmissions` (`pg_advisory_xact_lock` per user, `service.ts:36-38`) menyerialkan duplikasi, `AI_SUBMISSION_IN_PROGRESS`, dan hitungan kuota 24 jam dalam satu transaksi; kuota dihitung dari jam DB (`quota.ts:25`). Retry tidak menambah hitungan, dibatasi 3x lewat `audit_log` (`service.ts:163-167`). Urutan pemeriksaan sesuai spec (konteks -> panjang -> duplikat -> aktif -> kuota -> antrean).
- **Skor tak dapat dimanipulasi dari teks:** `overall_band` model diabaikan, dihitung ulang `roundToHalfBand(mean)` di kode; kap panjang/non-English/>=8.0 diterapkan di `scoring.ts:312-329` sebagai minimum; `injection_suspected` hanya menandai. Tidak ada jalur ke gerbang (hook kosong). Skor AI tidak meloloskan gerbang (ADR-003 #1).
- **Pertahanan prompt:** teks pengguna hanya di pesan `user` dalam satu pasang `<student_response id="{hex8 acak}">` (`prompts.ts:141`); netralisasi pembatas (semua varian atribut/spasi), token chat `<|...|>`, awal baris `system:/assistant:/user:`, pagar kode, potong 5000 (`text.ts:252-260`); aturan sistem "data tidak tepercaya" + canary rahasia yang menolak keluaran bocor (`evaluate.ts:30-34`); `format` JSON Schema + Zod `strictObject` (kunci tambahan ditolak, `contracts/ai.ts:206-214`) + satu perbaikan tanpa nilai masukan (`prompts.ts:181-195`). LLM tanpa tool/jaringan/DB; prompt tidak memuat email/nama/data pengguna lain.
- **Keluaran LLM tidak dipercaya di klien:** semua teks AI (komentar, koreksi, rewrite, transkrip) dirender sebagai node teks React; grep `dangerouslySetInnerHTML|innerHTML` pada `components/ai` bersih; anotasi inline memakai `indexOf` + potongan string (`lib/ai/annotate.ts`), bukan HTML; ada tes "teks AI dirender literal" (`ai.test.tsx:98`). `raw_output`, `prompt_version`, `error_code` evaluasi tidak ada di DTO (`ai/dto.ts:28-50`); log pipeline hanya id/model/status/durasi (diuji).
- **Fallback AI mati:** `AI_ENABLED=false` -> `FALLBACK_SELF_ASSESSMENT`, tanpa kuota/antrean; job `QUEUED` dibatalkan saat dimatikan (`dispatch.ts:440-456`); worker memeriksa saat mulai (`pipeline.ts:130-134`). Self-assessment memvalidasi kunci tepat dan nilai kelipatan 0.5, overall dihitung server.
- **Dispatch setelah commit + idempotensi:** `enqueue` dilakukan setelah transaksi (`service.ts:101`), id pg-boss disimpan, gagal -> `FAILED INTERNAL` + 503; `beginRun` mengunci baris job `FOR UPDATE` dan hanya memproses `QUEUED/RUNNING` sehingga eksekusi ganda no-op (`pipeline.ts:69-84`); penghitung percobaan di `async_jobs.attempt` (`pipeline.ts:104-119`).
