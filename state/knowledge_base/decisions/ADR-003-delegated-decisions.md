# ADR-003 — Keputusan yang didelegasikan ke Orchestrator

**Tanggal:** 2026-11-03
**Status:** `Accepted` (didelegasikan: human menyerahkan 100% keputusan ke rekomendasi Orchestrator sampai Fase 3 selesai; ditinjau ulang oleh human setelah Fase 3)

> Semua item di bawah mengikuti rekomendasi agen masing-masing. Human akan ditanya ulang setelah Fase 3. Perubahan lewat `_shared/change-management.md`.

| 30 | Bukti minimum rekomendasi Placement (QA W7 F-15-01) | **Diputuskan Orchestrator, perlu tinjauan human.** `recommended_tier = min(hasil_D4, 1 + floor(3 * dijawab / N))` (N = `placement.question_count`; N=25: <=8 jawaban Tier 1, 9-16 maks Tier 2, 17-24 maks Tier 3, 25 bebas). Alasan: Placement dapat diakhiri kapan saja dan 1-3 tebakan beruntung dapat melompati Tier 1-3 beserta Boss-nya; batas ini menuntut bukti sebanding dengan lompatan. Vektor uji spec 015 (25 jawaban) tidak berubah. Alternatif ditolak: syarat `dijawab >= ceil(N/2)` (kasar, melompat di tengah). Amandemen D4 spec 015. |

| 33 | Keputusan implementasi W8 (SPEC-016/017/020) | **Diputuskan Backend/Orchestrator, perlu tinjauan human.** (a) F-08-06: `time_spent_ms` tetap jujur tetapi jawaban setelah resume yang menggeser basis TIDAK dikreditkan ke bonus kecepatan (pengguna jujur yang kembali setelah > 60 dtk kehilangan kredit satu soal; pemanipulasi kehilangan seluruhnya); F-14-06 ditutup dengan melewati hitung ulang D8 untuk Boss. (b) SPEC-020 K3 "attempt IN_PROGRESS" ditafsirkan sebagai attempt hidup (EXAM sebelum deadline+5 dtk, PRACTICE aktif <= 24 jam) agar Drill yang ditinggalkan tidak mengunci set selamanya; jalur impor SPEC-019 tidak dijaga K3 (residual F-15-07). (c) Poin Boss: sekali per set Boss; aktivitas harian dicatat untuk Drill/Skip/Boss/learn-complete/Mini-Task, bukan Placement. (d) Prediksi band tanpa kunci advisory (menghindari deadlock); konsekuensi: pada balapan langka dua pemicu bersamaan riwayat dapat menyimpan titik sementara berbeda dan dikoreksi pemicu berikutnya (radar selalu dibaca dari skor teragregasi). |
| 34 | Batas manusia speed streak (QA W8 F-16-01) | **Diputuskan Orchestrator, perlu tinjauan human.** Kredit `within_target_time`/streak hanya bila `time_spent_ms >= 2000` (konstanta `MIN_HUMAN_MS`, rekomendasi QA opsi a); tidak memakai `presented_at` per soal (mengubah kontrak/UX). Koreksi klaim #33(a): F-08-06 hanya menutup vektor resume; jawaban beruntun di luar dan dikirim berselang > 2 dtk masih dapat dikreditkan (batasan diketahui; bonus tetap dibatasi G3 sekali per set). Pengguna yang menjawab satu soal sangat sederhana dalam < 2 dtk kehilangan kredit soal itu (diterima). Amandemen spec 016. |
| 35 | Riwayat poin dan zona waktu (QA W8 F-16-04, F-16-05) | **Diputuskan Orchestrator, perlu tinjauan human.** `GET /me/points` menyaring `ADJUSTMENT` (kontrak FE `PointSource` tidak memuatnya; `total_points` tetap memuat penyesuaian, sehingga jumlah riwayat bisa berbeda dari total bila admin pernah menyesuaikan; alternatif menambah nilai ke kontrak ditolak karena mengubah FE). `APP_TIMEZONE` divalidasi IANA saat boot (gagal cepat); pembacaan runtime tetap `process.env` dengan fallback (tes mengubahnya per kasus). |
| 36 | Kejujuran radar dan prediksi (QA W8 F-17-01, F-17-02) | **Diputuskan Orchestrator, perlu tinjauan human.** R1: sampel = jawaban terbaru per soal unik `(assessment_set_id, question_id)`, 50 terbaru; minimum `estimated_band` 10 soal unik (bukan 20 seperti usul QA, agar pelajar baru tetap melihat radar dalam 1-2 Drill); rentang prediksi `+/-0,5` bila sampel objektif terkecil >= 30, selain itu `+/-1,0`; `prediction.sample_size` (int/null) dan `prediction.low_sample` (boolean) aditif; FE menampilkan lencana "Indikatif" saat `low_sample`. Skor lama di DB tidak dihitung ulang massal (dikoreksi pada hitung ulang berikutnya per pemicu). F-17-03: DTO `components` pada titik BOSS sudah memuat komponen null (FE menandai indikatif). Amandemen spec 017. |
| 37 | Pagar konten dan attempt (QA W8 F-20-01..04) | **Diputuskan Orchestrator, perlu tinjauan human.** (a) K3 diperluas ke modul/sub-modul untuk transisi ke DRAFT/ARCHIVED (ditolak 409 `SET_HAS_ACTIVE_ATTEMPTS` bila set Drill/Skip di bawahnya punya attempt hidup), dan Gatekeeping `applyDrillResult`/`applySkipResult` toleran terhadap entitas yang hilang (skor tersimpan, progres tidak berubah) sebagai pengaman bila arsip lolos lewat DB/impor; (b) PRACTICE `IN_PROGRESS` yang basi (> 24 jam) atau beda `assessment_version` dengan set menjadi `ABANDONED` pada PUT/submit/GET (409 `ATTEMPT_NOT_ACTIVE`) dan pada POST /attempts (attempt baru); EXAM tidak diubah (K3 sudah menghalangi edit, `expire` tetap); (c) satu fungsi `hasActiveAttempts`/`activeAttemptSetIds` (`content/active-attempts.ts`) dipakai kurasi dan impor (evaluasi JSON/CSV + pemeriksaan ulang dalam transaksi publikasi dengan `FOR UPDATE` pada set); mengoreksi #33(b) "jalur impor tidak dijaga"; (d) publikasi impor `PUBLISHED` wajib `confirm_reviewed: true` bila batch memuat konten `AI_GENERATED_REVIEWED` (pemeriksaan cepat dari payload saat permintaan + pemeriksaan ulang origin DB di job; tanpa konfirmasi: 409 atau batch kembali `PREVIEW_READY` dengan `REVIEW_CONFIRMATION_REQUIRED`); `confirmed_by` di audit `IMPORT_PUBLISH_REQUESTED` dan `IMPORT_PUBLISHED`; `summary.has_ai_generated` aditif. Amandemen spec 019/020. |

| 39 | Impor CLI vs entitas PUBLISHED (E2E Fase 3 O-1) | **Diputuskan Orchestrator, perlu tinjauan human.** Temuan: `content:import` Golden Sample (paket DRAFT) menimpa isi Boss Tier 1 yang sudah PUBLISHED tanpa reviu (kunci alami = Tier; `applyContentPlan` mempertahankan status sehingga isi berubah di bawah status PUBLISHED). Keputusan: CLI tidak boleh mengubah entitas PUBLISHED secara diam-diam. UPDATE pada MODULE/SUB_MODULE/ASSESSMENT_SET berstatus PUBLISHED ditolak (exit 1, `published_overwrite_blocked`, juga pada `--dry-run`) kecuali flag eksplisit `--allow-published-overwrite`; UPDATE pada set dengan attempt hidup SELALU ditolak (`set_has_active_attempts`, fungsi `hasActiveAttempts` yang sama dengan SPEC-019/020) apa pun flag-nya. Status tidak pernah diturunkan oleh CLI. Jalur impor Admin (SPEC-019, F-19-01: PUBLISHED tetap tayang setelah UPDATE via preview+konfirmasi) tidak berubah. Alternatif ditolak: otomatis menurunkan ke DRAFT (menyembunyikan konten dari pelajar tanpa sengaja). Amandemen spec 004 (CLI). Dampak: alur seed lokal yang mengimpor ulang paket berisi perubahan pada entitas PUBLISHED kini perlu flag. |
